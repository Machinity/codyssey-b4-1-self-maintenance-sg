# F1. 서비스 로봇 온디바이스 Ubuntu — 위협 모델

> 미션 필수는 아닙니다. 00~09장을 끝낸 뒤, **"내가 한 설정이 현장에서 어떤 공격을 막는가"** 를 연결해 보는 문서입니다.

## 1. 현장 로봇은 데이터센터 서버와 무엇이 다른가

| 관점 | 데이터센터 서버 | 현장 서비스 로봇 |
|---|---|---|
| **물리 접근** | 출입 통제된 전산실 | 식당·병원·호텔 로비 — **누구나 만질 수 있음**, 도난 가능 |
| **네트워크** | 관리되는 사내망 | **고객사 Wi-Fi**(신뢰 불가), LTE, 수시로 끊김 |
| **관리자 접근** | 콘솔(IPMI), 상주 인력 | 원격만 가능. 실수하면 **출동(현장 방문)** |
| **규모** | 수십~수백 대, 동일 환경 | 수백~수천 대, **현장마다 환경이 다름** |
| **실패의 결과** | 서비스 중단 | 서비스 중단 + **물리적 위험**(충돌, 낙하), 영업장 운영 차질 |
| **자원** | 넉넉함 | 제한된 CPU/RAM, **플래시 저장장치(쓰기 수명)**, 배터리 |
| **수명** | 3~5년 교체 | 5~10년 운용 → OS 지원 기간(LTS) 관리가 중요 |
| **민감 데이터** | 서버 로그 | **카메라 영상, 매장 지도(SLAM), 고객 대화** → 개인정보 |

→ 결론: 로봇은 "**적대적인 환경에 혼자 놓인, 원격으로만 고칠 수 있는 컴퓨터**"입니다. 기본 보안 설정의 가치가 서버보다 훨씬 큽니다.

> Ubuntu 22.04 LTS 의 표준 보안 지원은 2027년 4월까지이고, Ubuntu Pro(ESM)로 연장할 수 있습니다. 로봇 제품 수명이 OS 지원 기간보다 긴 경우가 흔하므로, 제품 기획 단계에서 **OS 업그레이드 계획 또는 연장 지원**을 정해 둬야 합니다. 01장에서 본 것처럼 22.04 → 24.04 는 SSH 소켓 활성화 등 동작이 바뀌므로 "그냥 올리면 되는" 일이 아닙니다.

## 2. 지켜야 할 자산

| 자산 | 예 | 침해 시 영향 |
|---|---|---|
| 로봇 제어권 | 주행·팔 제어 프로세스 | 물리적 사고, 안전 문제 |
| 자격 증명 | 클라우드 API 키(`api_keys/`), 플릿 관리 인증서, SSH 키 | 다른 로봇·클라우드로 **확산**(lateral movement) |
| 고객/개인 데이터 | 영상, 음성, 매장 지도 | 개인정보 유출, 법적 책임 |
| 운영 기록 | 로그(`/var/log/agent-app`) | 사고 원인 분석 불가, **로그 변조로 흔적 은폐** |
| 소프트웨어 | 바이너리, 모델 가중치 | 지식재산 유출, 변조된 소프트웨어 배포 |
| 가용성 | 앱 프로세스, 디스크 공간 | 영업장 서비스 중단 |

## 3. 누가, 어디로 공격하나

| 공격 표면 | 대표 위협 | 이 미션의 대응 | 현장 강화 |
|---|---|---|---|
| 네트워크 서비스(SSH) | 봇의 무차별 대입, 기본 계정 | 포트 20022, root 차단 | 키 인증, VPN 뒤로, fail2ban ([F2](F2_원격접속과_네트워크.md)) |
| 네트워크 서비스(기타) | 디버그 포트, 개발용 서버 노출 | UFW default deny | 인터페이스별 규칙, 외부 실측 감사 |
| 앱 포트(15034) | 앱 취약점 공격 | 필요한 포트만 허용, 일반 계정 실행 | 출발지 IP 제한, systemd 샌드박스 ([F3](F3_서비스운영_systemd_로그_시크릿.md)) |
| 파일 업로드 | 악성 파일 업로드 후 실행 | 공유 디렉토리 분리 | `noexec` 마운트, 파일 검증 |
| 계정 | 퇴사자·공용 계정 악용 | 역할별 계정/그룹 | 개인 계정 + 중앙 인증, 접근 기록 감사 |
| 비밀 값 | 키 파일 탈취 | agent-core 전용 디렉토리 | 기기별 키, 디스크 암호화, 키 교체 |
| 물리 포트 | USB 로 부팅/키 탈취, 시리얼 콘솔 | (범위 밖) | BIOS/부트로더 잠금, `usbguard`, LUKS+TPM |
| 업데이트 경로 | 변조된 패키지(공급망) | (범위 밖) | 서명 검증, 사내 미러, A/B OTA |
| 모니터링 공백 | 공격·장애를 아무도 모름 | monitor.sh + cron + 로그 | 중앙 로그/메트릭, 경보, 하트비트 |

## 4. 미션 항목 ↔ 보안 원칙 매핑

| 미션 항목 | 적용된 보안 원칙 |
|---|---|
| SSH 포트 변경 | 공격 표면 소음 감소 (단독으로는 은폐일 뿐) |
| root 원격 차단 | 최소 권한, **책임 추적성** |
| UFW default deny + 2개 포트 | **기본 거부**(Default Deny), 공격 표면 최소화 |
| 역할별 계정/그룹 | 역할 기반 접근 제어(RBAC), 직무 분리 |
| 공유/보안 디렉토리 + ACL | 최소 권한, 데이터 분류에 따른 경계 |
| 환경 파일 root 소유 | 설정 **무결성**, 변조 방지 |
| 앱 root 실행 금지 | 권한 분리, 침해 반경 축소 |
| sudoers `ufw status` 한 줄 | 최소 권한(명령 단위) |
| monitor.sh + cron + 로그 | **탐지와 가시성**, 사후 분석 가능성 |
| 로그 회전·보존 | **가용성**(디스크 보호), 데이터 최소 보유 |

## 5. 참고할 만한 기준

- **CIS Benchmark for Ubuntu 22.04** — 가장 널리 쓰이는 OS 하드닝 기준. 이 미션의 항목 다수가 포함되어 있습니다. Ubuntu Pro 의 `usg`(Ubuntu Security Guide) 도구로 자동 점검할 수 있습니다.
- **IEC 62443** — 산업 자동화·제어 시스템 보안 표준. 산업용/물류 로봇 납품 시 요구되는 경우가 많습니다.
- **ISO 13482 / ISO 10218** — 서비스·산업 로봇의 **안전(Safety)** 표준. 보안 사고가 안전 사고로 이어질 수 있으므로 함께 고려합니다.
- **개인정보 보호법** — 카메라·음성 데이터를 다루는 서비스 로봇은 수집·보관·파기 정책이 필요합니다. 08장의 "30일 후 삭제" 같은 보존 정책이 이 요구와 연결됩니다.
