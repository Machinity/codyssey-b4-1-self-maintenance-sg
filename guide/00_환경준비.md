# 00. 실습 환경 준비

## 이 장의 목표

- Ubuntu 22.04 LTS 서버 VM을 만들고, 내 PC에서 SSH로 접속한다.
- 저장소(가이드·스크립트·앱)를 VM으로 옮긴다.
- **"콘솔 창은 절대 닫지 않는다"** 는 원격 운영 제1원칙을 몸에 익힌다.

---

## 1. 왜 컨테이너가 아니라 VM인가

| 필요한 것 | 컨테이너(Docker) | VM |
|---|---|---|
| UFW (커널 netfilter 제어) | 호스트 커널을 공유 → 권한 문제, 호스트 방화벽과 충돌 | ✅ 독립된 커널 |
| sshd 포트 변경 후 재접속 테스트 | 포트 매핑 때문에 결과가 왜곡됨 | ✅ 실제와 동일 |
| cron, systemd | 기본 이미지에 없음(PID 1이 셸) | ✅ 기본 탑재 |

서비스 로봇의 온디바이스 OS는 "베어메탈에 설치된 완전한 Ubuntu"이므로 **VM이 현장과 가장 가깝습니다.**

## 2. VM 만들기

### 2-1. 내 PC에 맞는 조합 고르기

| 내 PC | 하이퍼바이저 | Ubuntu 이미지 | 사용할 앱 바이너리 |
|---|---|---|---|
| Apple Silicon Mac (M1~M4) | [UTM](https://mac.getutm.app/) | Ubuntu Server 22.04 **ARM64** ISO | `agent-app-linux-arm64` |
| Intel Mac / Windows / Linux | VirtualBox 또는 VMware | Ubuntu Server 22.04 **amd64** ISO | `agent-app-linux-x86` |

> ISO는 https://releases.ubuntu.com/22.04/ (amd64), https://cdimage.ubuntu.com/releases/22.04/release/ (arm64) 에서 받습니다.

> ⚠️ **Multipass는 비추천**: `multipass shell` 은 내부적으로 SSH 22번을 사용합니다. 01~02장에서 22번을 닫으면 VM에 들어갈 방법이 사라집니다. 이는 현장 로봇에서 "원격 관리 에이전트가 쓰는 포트를 모르고 막아버리는" 사고와 똑같습니다.

### 2-2. 권장 사양

| 항목 | 값 | 이유 |
|---|---|---|
| vCPU | 2 | 앱이 CPU 부하를 일부러 발생시킨다 |
| RAM | 2 GB | 앱이 최대 약 256MB를 점유 → MEM 경고(10%)가 실제로 발생하는지 볼 수 있음 |
| Disk | 20 GB | DISK 80% 경고와 거리를 둔다 |
| 네트워크 | UTM: Shared Network / VirtualBox: **브리지** 또는 **호스트 전용 + NAT** | 내 PC → VM 으로 직접 접속 가능해야 함 |

### 2-3. 설치 시 선택 사항

- **Profile setup**: 사용자 이름을 `ops` 로 만듭니다. (이 가이드의 관리자 계정 이름. 다른 이름이어도 되지만 명령에서 바꿔 읽으세요.)
- **SSH Setup**: `Install OpenSSH server` 체크 ✅
- **Featured Server Snaps**: 아무것도 선택하지 않음 (로봇에 불필요한 소프트웨어 = 공격면)

## 3. 첫 부팅 후 기본 설정 (VM 콘솔에서)

```bash
# 버전 확인: "Ubuntu 22.04.x LTS", "jammy" 가 보여야 한다
ops@vm$ lsb_release -a
ops@vm$ uname -m          # x86_64 또는 aarch64 → 사용할 바이너리 결정

# 패키지 최신화 + 실습에 필요한 도구
ops@vm$ sudo apt update && sudo apt -y upgrade
ops@vm$ sudo apt install -y ufw acl cron tmux at bsdutils iproute2 procps
#   ufw  : 방화벽            acl  : getfacl/setfacl
#   cron : 주기 실행         tmux : SSH 가 끊겨도 살아있는 터미널
#   at   : "5분 뒤 자동 롤백" 같은 1회성 예약 (02장 현장 노트)
#   bsdutils : script 명령 (앱 부팅 출력 기록)

# 시간대: 로그 시각이 한국 시간으로 찍히도록
ops@vm$ sudo timedatectl set-timezone Asia/Seoul
ops@vm$ timedatectl        # "System clock synchronized: yes" 확인

# 호스트 이름: 로봇이 여러 대일 때 로그/프롬프트에서 구분되도록
ops@vm$ sudo hostnamectl set-hostname robot-01

# VM 의 IP 확인
ops@vm$ ip -br a
```

✅ 체크포인트: `lsb_release -a` 에 `Codename: jammy`, `ip -br a` 에 `192.168.x.x` 등 IP가 보인다.

> 🤖 **현장 노트 — 시간 동기화는 보안 기능이다**
> 로그 분석의 기본은 "여러 기기의 로그를 시간 순으로 맞춰 보기"입니다. 로봇의 시계가 3분 틀어져 있으면, 관제 서버의 경보와 로봇 로그를 맞춰볼 수 없습니다. 인증서 검증(TLS)도 시간이 틀리면 실패합니다. 현장에서는 `systemd-timesyncd` 또는 `chrony` 로 사내 NTP 서버에 동기화하는 것을 출하 기본값으로 둡니다.

## 4. 내 PC에서 SSH 접속 & 저장소 복사

```bash
# 아직은 기본 포트 22
mac$ ssh ops@<VM_IP>

# 저장소 전체를 VM 의 ops 홈으로 복사 (저장소 상위 폴더에서 실행)
mac$ scp -r codyssey-b4-1-self-maintenance-sg ops@<VM_IP>:~/
```

> GitHub에 올려둔 저장소라면 VM에서 `git clone` 해도 됩니다.

VM에서 확인:

```bash
ops@vm$ cd ~/codyssey-b4-1-self-maintenance-sg
ops@vm$ ls
ops@vm$ file agent-app/*          # ELF 64-bit ... x86-64 / ARM aarch64
ops@vm$ chmod +x agent-app/* scripts/*.sh

# 이후 가이드에서 반복해서 쓸 변수 (VM 아키텍처에 맞게 자동 선택)
ops@vm$ echo 'export REPO=~/codyssey-b4-1-self-maintenance-sg' >> ~/.bashrc
ops@vm$ echo 'export APP_BIN=agent-app-linux-$( [ "$(uname -m)" = aarch64 ] && echo arm64 || echo x86 )' >> ~/.bashrc
ops@vm$ echo 'export AH=/home/agent-admin/agent-app' >> ~/.bashrc     # AGENT_HOME 의 약칭 (ops 셸용)
ops@vm$ source ~/.bashrc && echo "$REPO / $APP_BIN / $AH"
```

✅ 체크포인트: `echo $APP_BIN` 이 `uname -m` 에 맞는 파일명을 출력한다.

> 💡 파일을 Windows에서 편집·복사했다면 줄바꿈이 CRLF일 수 있습니다. 스크립트 실행 시 `/usr/bin/env: 'bash\r': No such file or directory` 가 나오면 `sed -i 's/\r$//' 파일` 로 고칩니다.

## 6. 작업 규칙: 터미널 두 개 + 콘솔

이 미션 동안 항상 다음 세 개를 열어둡니다.

| 창 | 용도 | 왜 필요한가 |
|---|---|---|
| **VM 콘솔 창** (UTM/VirtualBox 화면) | 비상 출입구 | SSH·방화벽 설정을 망쳐도 여기로는 들어갈 수 있다 (**Out-of-Band 접근**) |
| SSH 터미널 A | 작업용 | 설정 변경 |
| SSH 터미널 B | 검증용 | "새 접속이 되는가"를 별도로 확인 |

> 🤖 **현장 노트 — Out-of-Band(OOB) 관리**
> 데이터센터 서버에는 IPMI/iDRAC 같은 원격 콘솔이 있지만, 현장 로봇에는 보통 없습니다. 그래서 로봇 회사들은 ① 셀룰러 모뎀을 통한 별도 관리 채널, ② 로봇 본체의 유지보수 포트(USB 시리얼), ③ 현장 담당자의 로컬 접근 절차를 준비합니다. **OOB가 없으면 SSH 설정 실수 = 출동**입니다. 이 미션에서 VM 콘솔 창이 그 역할을 합니다.
