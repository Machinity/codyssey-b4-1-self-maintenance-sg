## 1. SSH 보안 설정

### 1-1. 설정 내용

`/etc/ssh/sshd_config.d/10-agent-hardening.conf`
```
# /etc/ssh/sshd_config.d/10-agent-hardening.conf
#
# - Ubuntu 22.04 의 /etc/ssh/sshd_config 는 첫 줄 근처에서 이 디렉토리를 Include 한다.
# - sshd 는 "같은 키워드는 처음 나온 값이 이긴다(first match wins)".
#   → 파일 이름을 10- 으로 시작해 50-cloud-init.conf 등 다른 drop-in 보다 먼저 읽히게 한다.
# - 단, Port 는 예외적으로 "누적"된다. 메인 파일에 'Port 22' 가 활성화되어 있으면
#   22 와 20022 를 둘 다 연다. 메인 파일의 Port 줄은 반드시 주석 상태여야 한다.
#
# 적용 전 반드시: sudo sshd -t   (문법 검사, 출력 없으면 정상)

# [미션 필수] SSH 포트 변경
Port 20022

# [미션 필수] root 원격 로그인 차단
PermitRootLogin no

# ---- 이하 현업 권장(선택) ---------------------------------------------------
# 무차별 대입 시도 횟수 제한
MaxAuthTries 3
LoginGraceTime 30
# 로봇/서버에 GUI 포워딩은 불필요
X11Forwarding no

# [주의] 아래는 "공개키 로그인이 되는 것을 확인한 뒤" 에만 켠다. (잠김 사고 방지)
#PasswordAuthentication no
#KbdInteractiveAuthentication no
# 접속 가능한 그룹을 제한 (자신의 관리 계정이 이 그룹에 있는지 먼저 확인)
#AllowGroups sudo agent-core
```

### 1-4. 왜?

1. 포트를 20022로 바꾸는 것만으로 안전하다고 할 수 없는 이유는?
   - 포트는 무차별 대입 공격 등이 쉽게 공격할 수 있는 포트인 22번 포트를 피하기 위함이지, 안전 장치라고 할 수 없다. 단순히 이사를 가서 호수가 바뀌었다고 정작 잠금장치가 없으면 안전하다고 할 수 없는 것과 같다.
2. root 원격 로그인을 막으면 "책임 추적성"이 왜 좋아지는가?
   - root 원격 로그인이 허용된다면 누가 관리자 권한으로 접속해서 수정했는지 알 수 없지만, 개별 계정을 생성하고 각자 sudo 명령어를 쓴다면 로그에 누가 sudo 명령어를 사용하고 관리자 권한을 사용했는지 기록이 남게 된다.
3. `sshd` 를 재시작해도 기존 SSH 세션이 끊기지 않는 이유는?
   - 기존 ssh 세션에 대한 접근 허용 정보가 남아있기 때문이다.
4. 파일을 grep 하는 것보다 `sshd -T` 로 검증하는 것이 나은 이유는?
   - 설정 파일이 시스템에 적용된 후, 해당 시점에서 실제 실행중인 정보가 출력되기 때문이다.
5. 메인 파일에 `Port 22` 가 살아 있으면 어떻게 되는가?
   - 포트 설정은 무시되지 않기 때문에 22번 포트도 접근을 허용한다.
